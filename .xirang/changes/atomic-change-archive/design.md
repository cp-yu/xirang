## Context

目前 CLI 的 `sync` 负责模型写入，`archive` 只检查是否有 pending Delta 后移动目录；两者之间不存在共同回滚边界。Snack 已将它们串联，Archive 提示词则在调用前另行检查 Seal、制品与任务。只串联两条命令既不能保证移动失败时撤销模型写入，也会使放弃路径被无关的检查拦截。

## Goals / Non-Goals

**Goals:** 一个收束入口，明确区分交付、免 Seal 交付和放弃；将进程内的写入失败纳入同一错误处理范围。保留现有三个能力身份，按现有业务规格 Kind 整理，不重排层级。

**Non-Goals:** 不更改 Review/Opt/Seal 的形成规则，不证明 quick 的实现经过验证；不管理进程崩溃恢复、归档撤销或历史迁移，不增设放弃理由文件。正常交付后的 Git 操作仍由 Agent 负责，CLI 不提交代码。

## Decisions

1. **先分模式，再读取门禁输入。** CLI 使用显式选项，默认交付、quick 交付、abandon 留档互斥。相互矛盾的 `--quick --abandon` 在解析时拒绝，`--yes` 只代替交互。解析合法名称后只在活动目录和两种已知归档位置查找；已归档的查询不再次走门禁。放弃位于 Quality、制品、Delta 编译和 Git 指导之前：复用 `getTaskProgressForChange` 的 Goals 统计，先提示可核实的进度，再确认一次。文件缺失不作实现状态判断，不阻塞。调用方必须能区分本次实际移动、取消和查到已有结果，避免误触发交付后续操作。
2. **交付使用同一份输入。** 从同一正式快照编译完整 Delta 与 Expected Semantic Model，使用已有 `allowAlreadyApplied` 的实体类型＋identity＋目标内容判断；以该快照建立写前内容和指纹。拒绝吞掉真正的前置条件冲突。确认前只读校验并准备快照；确认后在提交窗口复核基线、Delta 和适用的 Seal，并探测有歧义的路径是否发生大小写别名；只写目标差异，并对实际封存的内容复核 Delta 与 Seal。不要先运行独立 Sync，再在已改变的基线上重新解释一遍 Delta。旧版同步后目标已经完全一致时，空写入清单仍然要完成目录移动。
3. **复用有前像的回滚。** 所有归档模式在同一工作区互斥提交；各调用在确认后、写入前创建进程 claim，发现其他活跃 claim 则停止，自己的 claim 保留至提交或补偿完成。`applySemanticTreeManifest` 在其 try/catch 内执行 `postWrite`，封存前用普通读取器复核 Formal 目标，失败则恢复已应用条目并清理本次新建的空目录。只在源文件系统内把活动目录 rename 到独占私有路径；不在最终路径使用可能覆盖现有目录的 rename。暂存后分别独占创建目标目录、普通文件和符号链接并核对 Delta，安装成功后只删除被移走的副本，不删除原活动路径。清理被移走的源后再确认活动路径未被重建；发现重建则用独占暂存恢复原始内容并报告其保留位置，不覆盖任一输入。目标不得覆盖；预留后出现其他写入也应拒绝，补偿逐项撤销本次拥有的条目。安装前在目的目录旁创建 `.pending` 标记，成功提交才解除；失败时即使活动目录恢复失败也独立撤销目的条目，无法清完就保留标记，重试不会把残留目录当作完成记录。交付与放弃均对普通制品、目录和链接复核完整快照。文件系统连补偿都拒绝时报告两类错误。输出失败不撤销已提交结果。
4. **两个历史位置代表两个结果。** 日期命名沿用现行规则；正常位置和固定 `abandoned` 子目录各用明确的路径组件。Windows/macOS/Linux 均用 `path.join`/`path.resolve`，不拆原生路径字符串。按名称精确核对日期目录余下的 Change 名，不把相同后缀的其他 Change 当成本次结果。两个位置均不得覆盖已存在的目标；--json 继续区分机器可读结果与诊断。返回已有位置时不改动其内容。
5. **提示词按结果而非目录移动触发。** Archive 只在用户选择 quick 时豁免 Seal；放弃先进入独立分支，既不要求先完成 Apply，也不加载交付所需的 Git 清理流程。普通和 quick 保持交付后的既有 Git 边界。Snack 快速提示只保留合并后的命令；Propose 仍只预览。按现有 workflow manifest 和受管清单逐项投影对应的 skills、references 与工具面，不通过文本匹配批量重写项目文件；保留历史、用户文件以及工作面同步这一不同语义的 sync。更新项目定义中对应的当前行为描述，不重写无关定义。

## Risks / Trade-offs

- **进程终止后可能处于中间状态** → 不做持久化恢复日志，不承诺多路径的瞬时可见性。本机已退出进程的 claim 不阻塞后续调用，也不触发任何模型回滚。Agent 或用户核对 Git diff、Formal 与活动/归档目录（包括可能留下的 `.archive-source-*`）；仅在确认归档进程已结束后才能清理遗留标记，不整体回退工作区。
- **未经 Quality 的交付被误认为已验证，或放弃后把已写代码合并** → 显示实际模式与结果；放弃不走交付后续工作。拒绝模式冲突比设置隐式优先级更可预测。
- **旧命令失效** → 直接移除，不将旧 sync 映射为会归档的命令。既有已同步活动 Change 可以只完成封存；已有归档保持可查。

## Verification

以 CLI 输出、活动/归档目录的字节和正式模型前后状态为证据。沿用 archive 核心与集成用例作为交付入口，保留模型合并、只改目标单元、写入失败和目录移动补偿的独立覆盖。独立 sync 命令和旧 bypass 的成功行为已退役：将仍有效的模型行为转到合并入口，删除与新目标相反的断言，保留旧用法被拒绝的检查。对目录移动注入可捕获错误，区分“未写”“已写须回滚”“已提交仅未收到回执”。不用强杀进程证明不承诺的自动恢复。

提示词以实际模式路由和禁止操作判断；精确文本仅覆盖协议命令、必要门禁和退役 token，不锁定解释性文字。一次性核对生成面、help、补全及现行说明的一致性；Windows CI 检查实际路径/移动行为，不以某一种路径分隔符的文本比较代替。
