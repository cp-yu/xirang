# Research: Subagent/Agent File Conventions for AI Coding Tools

> Focus: Claude Code, Codex, Pi, OpenCode — skills vs AGENTS.md vs agents/*.md

## Summary

All four tools (Claude Code, Codex, Pi, OpenCode) support **project-local skills** via a `<toolDir>/skills/<skill-name>/SKILL.md` structure with YAML frontmatter (`name`, `description`, `license`, `compatibility`, `metadata`). **None** of these tools natively support an `agents/*.md` convention in their tool directory; the `agents/*.md` pattern is a GitHub Copilot (`<toolDir>/agents`) convention only. Pi has a `.pi/agent/` directory used for agent configuration, but it stores `AGENTS.md` (a single file), not a directory of multiple agent `.md` files. All four tools are **skills-only** in OpenSpec's current workflow surface — commands/slash-files are legacy artifacts.

## Findings

### 1. All four tools use the same `skills/openspec-*/SKILL.md` structure

| Tool | Skills path | Invocation syntax | Legacy command pattern |
|------|-------------|-------------------|----------------------|
| **Claude Code** | `.claude/skills/openspec-*/SKILL.md` | `/openspec-<skill>` | `.claude/commands/openspec/*.md` |
| **Codex** | `.codex/skills/openspec-*/SKILL.md` | `$openspec-<skill>` | `.codex/prompts/openspec-*.md` (skills-only now) |
| **Pi** | `.pi/skills/openspec-*/SKILL.md` | `/skill:openspec-<skill>` | `.pi/prompts/opsx-<id>.md` |
| **OpenCode** | `.opencode/skills/openspec-*/SKILL.md` | `/opsx-<slug>` | `.opencode/command/opsx-*.md` / `openspec-*.md` |

Source: `dist/core/config.js` (AI_TOOLS array), `dist/core/templates/transforms/builtin-transforms.js` (invocation transforms), `dist/core/legacy-cleanup.js` (legacy patterns)

### 2. SKILL.md frontmatter fields

All four tools share the same YAML frontmatter schema in SKILL.md files, generated by `dist/core/shared/skill-generation.js`:

```yaml
---
name: "<skill-name>"
description: "<description>"
license: "MIT"
compatibility: "Requires openspec CLI."
metadata:
  author: "openspec"
  version: "1.0"
  generatedBy: "<openspec-version>"
---
```

The template object (defined in `dist/core/templates/workflows/*.js`) supports these fields:
- `name` (required string) — skill display name
- `description` (required string) — what the skill does
- `instructions` (required string) — the full body content
- `license` (optional string, default "MIT")
- `compatibility` (optional string, default "Requires openspec CLI.")
- `metadata` (optional object with `author` and `version`)

Source: `dist/core/shared/skill-generation.js` (generateSkillContent function), `dist/core/templates/workflows/propose.js` (template shape)

### 3. No "agents/*.md" support in Claude Code, Codex, Pi, or OpenCode

- **Claude Code**: Only reads `.claude/skills/` for skills. No `.claude/agents/` pattern documented or detected anywhere in OpenSpec's codebase. The legacy `.claude/commands/openspec/` directory existed for slash commands but is no longer generated.
- **Codex**: Only reads `.codex/skills/`. No `.codex/agents/` pattern. Legacy commands were `.codex/prompts/openspec-*.md` (now skills-only, no command generation).
- **Pi**: Has `.pi/agent/AGENTS.md` — a single file for agent configuration, not a directory of multiple `.md` files. Also supports `.pi/skills/`.
- **OpenCode**: Only reads `.opencode/skills/`. No `.opencode/agents/` pattern. Legacy commands were `.opencode/command/opsx-*.md`.

The `agents/*.md` convention (a directory of markdown files acting as agent definitions) appears only in:
- **GitHub Copilot**: `.github/agents` is listed in `detectionPaths`. GitHub Copilot is the only tool in OpenSpec's AI_TOOLS that references an `agents` path.
- **Root `AGENTS.md`**: A single project-root `AGENTS.md` file is supported by some tools (Amp, VS Code extensions, etc.) but is treated as a **legacy config file** by OpenSpec — it can contain marker blocks but is NOT a multi-agent directory.

Source: `dist/core/config.js` (AI_TOOLS entries with detectionPaths), `dist/core/legacy-cleanup.js` (LEGACY_CONFIG_FILES includes root AGENTS.md)

### 4. Tool/model config in skills

Skills do **not** carry tool/model configuration. The SKILL.md frontmatter has:
- `compatibility` — a human-readable string (e.g., "Requires openspec CLI.")
- No `model`, `temperature`, `provider`, or other inference parameters

Tool-specific invocation transforms are applied at **generation time** (the `/opsx:propose` → `$openspec-propose` replacement), not through frontmatter.

Source: `dist/core/templates/transforms/builtin-transforms.js`

### 5. Name and description fields

Both are present in SKILL.md frontmatter:
- `name` — kebab-case identifier (e.g., `openspec-propose`)
- `description` — one-line human-readable summary

These are the canonical name/description fields. No additional `title` or `label` fields exist in the frontmatter schema.

### 6. Invocation/delegation behavior

| Tool | Skill invocation | Subagent delegation |
|------|-----------------|-------------------|
| **Claude Code** | `/openspec-<skill>` | Supports subagent delegation via `claude` (spawns subprocess). Internal skills (`openspec-reviewer`, `openspec-optimizer`, `openspec-impact-sweeper`) installed but NOT user-facing workflows. |
| **Codex** | `$openspec-<skill>` | Supports subagent delegation. Internal skills installed. |
| **Pi** | `/skill:openspec-<skill>` | Has `Skill Delegation Protocol` documented in skill files — certain internal skills must be delegated to a subagent. |
| **OpenCode** | `/opsx-<slug>` | Supports subagent delegation. Internal skills installed. |

Internal subagent skills (installed alongside workflow skills):
- `openspec-reviewer`
- `openspec-optimizer`
- `openspec-impact-sweeper`

These are **not** user-facing workflows — they are invoked programmatically by the main workflow skills.

Source: `dist/core/templates/manifest/registry.js`, `.pi/skills/openspec-explore/SKILL.md` (Skill Delegation Protocol section)

### 7. AGENTS.md vs skills

- **`AGENTS.md`** (project-root or `<toolDir>/agent/AGENTS.md`): A single file for agent instructions/configuration. Used by Pi (`.pi/agent/AGENTS.md`) and by some other tools at project root. OpenSpec treats root `AGENTS.md` as a legacy config file that can contain marker blocks.
- **`skills/*/SKILL.md`** (tool subdirectory of skill files): Used by all four tools. This is the **active** workflow surface for OpenSpec. Each skill is a self-contained markdown file with frontmatter in a named subdirectory.

Source: `dist/core/config.js`, `dist/core/legacy-cleanup.js`

### Dropped

## Gaps

1. **External primary docs**: The tool vendors' own documentation (Anthropic docs for Claude Code, GitHub docs for Codex, etc.) could not be consulted directly due to tool constraints. OpenSpec's source code is authoritative for the *skill interface* these tools support, but vendor-specific documentation about `agents/*.md` support may exist outside this project.

2. **Pi's `.pi/agent/AGENTS.md` format**: While OpenSpec detects and writes `.pi/agent/AGENTS.md`, the exact schema of that file (beyond being a single AGENTS.md) is not documented in this codebase. It may support frontmatter fields differently from the SKILL.md format.

3. **Root `AGENTS.md` conventions for non-OpenSpec tools**: Which tools at project root read `AGENTS.md` and what schema they expect is not detailed here. Legacy `AGENTS.md` at project root was used by multiple tools (Amp, VS Code extensions, etc.) but OpenSpec only removes marker blocks from it, it doesn't generate it.

4. **Codex command file format**: Codex previously used `.codex/prompts/openspec-*.md` for command files. The format of these prompt files (beyond being markdown) is not documented in OpenSpec's source.

## Unknowns requiring local implementation decisions

| Question | Impact | Suggested resolution |
|----------|--------|---------------------|
| Should OpenSpec support `<toolDir>/agents/*.md` (multi-agent directories)? | Only GitHub Copilot supports this today. Would require new tool definition. | Defer — no demand from current toolset. |
| Should skills support tool/model configuration (e.g., `model: claude-sonnet-4`, `temperature: 0.2`) in frontmatter? | Would enable per-skill model routing. Not currently supported. | Add as optional frontmatter fields with tool-specific defaults. |
| What should the `.pi/agent/AGENTS.md` format be for Pi-specific agent config? | Pi reads this file. OpenSpec currently leaves it unmanaged. | Define a schema for Pi's agent-level config distinct from skill frontmatter. |
| Should OpenSpec generate root `AGENTS.md` or only manage tool-specific skill files? | Some tools read root AGENTS.md. Currently legacy-only. | Decision: keep root AGENTS.md as user-managed; OpenSpec only manages tool-specific skills. |
